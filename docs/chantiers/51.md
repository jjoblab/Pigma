## Le design Material (le système de design d'Android Studio)

Consulté pour le dessin et le positionnement. Les pages m3.material.io
se rendent en JavaScript — le texte n'en est pas venu ; ce qui suit
vient de la connaissance Material Design 3 du modèle consulté, valeurs
INDICATIVES (à vérifier au pixel avant un travail de finition).

**Menus** : rayon 4 dp, élévation niveau 2 (ombre 3 dp), fond
surfaceContainer, texte onSurface ; s'ouvre SOUS l'ancre aligné à son
bord gauche, la retourne au-dessus ou se décale pour rester dans
l'écran, un vide de ~4 dp la sépare de l'ancre ; entrées de 48 dp.

**Infobulles** : plain — plein, ~24 dp, rayon 4 dp, texte 14 sp, vide
de ~8 dp de l'ancre, sans flèche ; rich — rayon 8 dp, ~12 dp de
marge, flèche optionnelle, largeur max 320 dp. Les deux se
repositionnent (retournement ou décalage) pour ne jamais sortir de
l'écran, apparaissent en fondu.

## Notre popups contre ces règles

| Règle M3 | Notre état | Écart |
| --- | --- | --- |
| Rester dans l'écran (retourner/décaler) | la popup ancrée se borne aux bords et passe SOUS l'ancre sans place | conforme |
| Rayon 4 dp | dp(4) | conforme |
| Vide entre ancre et popup | dp(4) | conforme (menus) |
| Largeur bornée (320 dp) | coupée au nombre de caractères — la gouttière fixe la chasse, pas les dp | écart assumé : chasse fixe |
| Fondu d'apparition | apparaît d'un coup | à faire un jour |
| Ombre/élévation | plate, bord bleu | écart assumé : dessin Canvas sans coût d'ombre |
| Bord gauche aligné à l'ancre | la colonne d'ancrage | conforme |

**La feuille du haut** : aucun besoin ne la justifie aujourd'hui (le
diagnostic vit dans le panneau du bas). Décision : elle ne se fait
pas — le prompt exige « aucun module ni package créé au cas où », la
même règle vaut pour les popups.
