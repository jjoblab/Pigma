## Le correctif D1 que les vraies classes ont épinglé

Le défaut D1 du rapport : `onSaveInstanceState()` construisait un
`Bundle` nu SANS appeler `super` — le contrat d'Android exige
`BaseSavedState`. La dispatch réelle du cadre
(`saveHierarchyState`) lève `IllegalStateException` sur ce contrat
brisé ; les stubs ne pouvaient pas le voir ; Robolectric l'a fait
remonte naturellement.

Le correctif vit dans `EditorView` :

- `EditorView.SavedState extends View.BaseSavedState` porte le
  curseur, l'ancre, le défilement ;
- `onSaveInstanceState()` appelle `super.onSaveInstanceState()` et
  range l'état dans le `SavedState` ;
- `onRestoreInstanceState()` redescend au `getSuperState()` du
  cadre avant de relire ;
- `CREATOR` public : la parcelle fonctionne.

Le scénario du harnais réel le vérifie : identification posée,
`saveHierarchyState` ne lève pas, le `SavedState` s'y lit, le
curseur revient après restauration, un état nul ne lève pas.
