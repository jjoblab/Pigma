# Chantier 100 — A2 : le document par onglet (l'écran et le protocole)

Le défaut (A2 du plan des onglets) : l'écran de démonstration
montrait UN document sous UNE URI (`file:///demo.java`) pour six
onglets — le serveur de langage recevait du XML ou du Lua sous le
nom de `demo.java` (ses diagnostics, ses ampoules et ses correctifs
de l'ancien contenu arrivaient sur l'onglet neuf), et la liaison
restait sourdement attachée à l'onglet parti.

## Le correctif

### La façade : `LspEditor.switchDocument(uri, languageId)`

Le document ouvert côté serveur se CHANGE : l'onglet qui s'en va
se FERME (`didClose` à la voie directe ; détachement au registre —
le dernier éditeur d'un langage y ferme son serveur, la définition
du serveur vit désormais dans la façade pour rattacher le document
neuf), celui qui arrive s'OUVRE au TEXTE COURANT de la vue et au
langage donné. En chemin : les génération d'annulation/survol/
surlignage AVANCENT (les réponses en vol de l'ancien document se
périment — personne n'ouvrira de carte d'une réponse tardive), les
vues du serveur se rangent (surlignages, indices, plis, jetons), la
pompe du document neuf repart. Le même document ne repart pas ; la
vue doit déjà porter le texte du document qui arrive (l'hôte
restaure AVANT d'appeler — le `didOpen` emporte le texte restauré).

### L'écran : un document par onglet

- Chaque onglet porte son URI (`file:///demo.java`, `.xml`,
  `.json`, `.kt`, `.lua`, `.sql`) et son `languageId` — posés à
  l'ouverture (`setHostDocument`).
- Le PASSAGE d'onglet : l'état de l'onglet qui s'en va se garde,
  celui qui arrive se rend (chantier 99) — puis le serveur suit :
  même langage, `switchDocument` ; autre langage, la liaison SE
  DÉBRANCHE (le serveur de démonstration ne voit que des documents
  Java : aucun onglet non-Java ne lui parle, aucune requête ne
  part). Le bouton LSP y revient.
- La RÉOUVERTURE du même onglet (les récents, le harnais) rouvre le
  document vivant comme avant — l'instantané sauvegardé n'y sert
  PAS (il serait périmé : l'écran a vécu depuis son départ). Le
  défaut s'est vu au vieux harnais : la réouverture restaurant un
  état périmé, le curseur sautait et le scénario suivant tapait à
  côté — la sémantique « le passage seul sauvegarde » l'a tué.
- Les hors normes (le gros fichier, le cycle 50k, le bouton Lua)
  débranchent l'onglet courant (`currentTab = null`) : leur document
  ne se sauvegardera pas sous un nom d'onglet.
- La rotation : l'onglet restauré redevient le courant.

## La preuve

- `TabDocumentIT` (Robolectric) :
  `theSwitchOpensTheNewDocumentAtTheServer` — le serveur GÉNÉRIQUE
  (aucun document pré-ouvert) publie ses diagnostics à l'URI du
  document NEUF après le passage (preuve du `didOpen` à la bonne
  URI, au texte restauré — l'avis compte LES parenthèses du texte
  neuf), le retour publie à l'URI de retour, le MÊME document ne
  republie rien. `theTabsCarryTheirDocuments` — l'écran réel : le
  passage Java → XML porte le document XML et son URI côté hôte, le
  serveur Java SE DÉBRANCHE (le bouton revient), le retour à Java
  rend le document ET son annulation (l'édition d'avant le voyage
  se défait). Les deux ÉCHOUENT sur le code d'avant (vérifié).
- `./gradlew check` **vert** (les six modules, politique comprise),
  le vieux harnais 51/51 (le scénario du protocole étendu y éprouve
  le surlignage, l'aller-à, le renommage — après le passage aux
  onglets à états).

## Les limites honnêtes

- Le `didClose` de la voie directe ne se prouve pas au serveur de
  démonstration (il n'en publie rien) : il se lit au code et
  s'éprouve par le débranchement de l'écran ; un serveur de test
  enregistrant les fermetures le dirait — le harnais n'en a pas.
- Le bouton « LSP Lua » (EmmyLua réel) ouvre le document Lua HORS
  onglet comme avant : le passage à l'onglet Lua d'EmmyLua
  (`switchDocument` vers `file:///demo.lua`) n'a pu s'éprouver sans
  appareil (le binaire natif ne vit pas au harnais) — le code y
  passe par la même voie que le test, le risque se limite au
  comportement d'EmmyLua face à un fichier hors de son espace.
