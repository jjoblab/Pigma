# Chantier 39 — le serveur de langage Lua réel, par processus

## Pourquoi ce chantier

La liste des restantes l'attendait : « le branchement d'un serveur de
langage hors processus — `overProcess` est prêt et testé dans `:lsp` ;
il attend qu'un serveur réel embarquable se présente sur l'appareil ».
Le propriétaire l'a apporté : **EmmyLua 0.25.1** (emmylua-analyzer-rust,
le serveur LSP de Lua écrit en Rust), que l'éditeur de référence
embarque en exécutables Android indépendants —
`jniLibs/<abi>/libemmylua_ls.so` (le nom `.so` est l'astuce : le
paquetage Android l'extrait vers `nativeLibraryDir`, le seul répertoire
où un exécutable vit depuis une application ; ce sont des PIE
autonomes, pas des bibliothèques JNI). Objectif du propriétaire : « elle
permettra de bien tester tous les fonctionnalités lsp » — le protocole
entier, contre un vrai serveur, pas une maquette.

## Ce qui a changé

### Le protocole a appris du serveur réel (deux leçons, deux correctifs)

Le premier branchement a échoué — et c'est le servicedu vrai serveur :

1. **La poignée de main complète.** EmmyLua a refusé le premier
   document : « expected initialized notification ». La notification
   `initialized` (après la réponse d'`initialize`) manquait — le
   serveur de démonstration s'en moquait, le vrai l'exige. La liaison
   l'envoie désormais à la conclusion de la négociation.
2. **Le genre de synchronisation se négocie.** Le survol marchait à
   l'ouverture, rendait null après une édition : la liaison envoyait
   toujours ses deltas par plage, EmmyLua déclare la synchronisation
   INTÉGRALE (le README du serveur le dit) — il ignorait la plage et son
   document désynchronisait. La liaison lit désormais le
   `textDocumentSync` des capacités : le serveur incrémental reçoit
   ses deltas (le chemin des chantiers 25-26, couvert par les tests
   d'un serveur d'essai qui déclare l'incrémental), le serveur
   intégral ou silencieux reçoit le texte entier (la notification sans
   plage, légale partout — le défaut sûr). `didChange` garde l'ombre
   dans les deux cas.

### Le harnais : le protocole complet contre le vrai serveur

`lsp/src/test/.../EmmyLuaProcessTest` lance le binaire **Linux de
bureau** d'EmmyLua 0.25.1 (la version glibc 2.17 de la publication
amont — les `.so` Android ne tournent que sur Android : interprète
`/system/bin/linker64`) par `overProcess` et éprouve la chaîne entière :
l'initialisation négocie, `didOpen` part, **le survol décrit la table
locale** (le markdown du serveur porte le type déduit), **la
complétion propose la table locale** (`caisse` entre les_globals),
l'édition par delta-négocié-texte-entier tient (le survol répond après
le changement), **le texte erroné publie ses diagnostics** (un `if`
sans `end`), l'arrêt ferme le processus. Le binaire se cherche par
`EMMYLUA_LS` (défaut : l'emplacement du bac) ; absent, le test
s'ignore — le build reste vert sans le serveur. Le diagnostic à la
main (scripts/diag-emmylua.py) a servi à isoler le coupable avant le
correctif.

### Le sample : le bouton « LSP Lua »

Le bouton lance le vrai serveur sur l'appareil : l'exécutable vient de
`nativeLibraryDir`, l'espace de travail vit dans `cacheDir/emmylua`
(la bibliothèque standard Lua s'y extrait par `--resources-path`, le
stderr s'y journalise), `demo.lua` s'écrit en vrai fichier (l'URI du
protocole pointe dessus), la liaison `overProcess` parle LSP sur
l'entrée/sortie standard du processus. L'éditeur passe au Lua (le
lexeur du chantier 38) : le survol du serveur prime sur l'index local,
la complétion du serveur monte au bandeau, les diagnostics comptent au
panneau — les mêmes fournisseurs que la démo, paramétrés par l'URI de
session. Débrancher coupe le processus. Le bouton « LSP » (démo, en
processus) vit à côté : le même détachement les relie — brancher l'un
débranche l'autre.

**Les architectures embarquées** : `arm64-v8a` et `x86_64` (13,9 Mo de
binaires — l'appareil et l'émulateur de bureau ; `armeabi-v7a` et
`x86` restent dehors, le bouton le dit s'il manque : « le serveur
EmmyLua manque pour cette architecture »). La licence MIT d'EmmyLua
vit dans `assets/licenses/emmylua`. La décision d'architecture se
documents ici : l'ajouter à un autre ABI est une copie de fichier.

## Ce qu'on voit (comment rejouer)

    EMMYLUA_LS=/home/z/my-project/tools/vendor/emmylua/emmylua_ls \
      scripts/run-lsp-tests.sh jo.pigma.lsp.EmmyLuaProcessTest
    # OK (1 test) — ~1 s contre le vrai serveur

Sur l'appareil : bouton « LSP Lua » — l'éditeur passe au Lua, le
panneau compte les diagnostics d'EmmyLua (« LSP : N diagnostic(s) —
EmmyLua hors processus »), le survol d'un mot rend la documentation du
serveur, « gr » propose au bandeau. La démo Lua porte volontairement
un texte sain ; une erreur y entrera déclenchera le compteur.
