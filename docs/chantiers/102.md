# Chantier 102 — B0 : le module `:ai`, pur, ce que l'hôte implémente

Le principe non négociable (B0 du plan de l'IA) :

> **Pigma ne connaît aucune IA.** Ni fournisseur, ni modèle, ni URL,
> ni clé d'API, ni protocole réseau, ni SDK. Pigma FACILITE
> l'intégration de l'IA dans l'application de l'hôte : il définit
> une interface que l'hôte implémente, fournit l'interface
> utilisateur, prépare le contexte et applique les modifications en
> sécurité. C'est l'hôte qui choisit où partent les données et qui
> paie.

## Le module

`:ai` en Java pur (le test de pureté ArchUnit y veille comme au
cœur — aucune dépendance à Android), uniquement des types de
données et des interfaces :

- **`AiBackend`** — ce que l'hôte implémente : `capabilities()`
  (les tâches acceptées, le flux géré — seules celles-ci
  apparaîtront dans l'interface de Pigma) et `start(request,
  listener)` (rend VITE une poignée annulable ; les rappels peuvent
  venir de n'importe quel fil ; une issue unique : complète OU
  erreur).
- **`AiListener`** — le delta facultatif du flux, l'issue
  heureuse, l'issue malheureuse.
- **`AiCall`** — l'annulation idempotente.
- **`AiError`** — cinq familles de panne (INDISPONIBLE, ANNULÉ,
  DÉLAI, REFUSÉ, INTERNE) : une phrase d'interface par famille, le
  détail de l'implémentation dans le message.
- **`AiTask`** — expliquer, expliquer l'erreur, corriger, modifier
  la sélection, compléter en ligne, documenter, écrire le test.
- **`AiRequest`** — le contexte préparé : préfixe/suffixe,
  sélection, instruction, diagnostics, bloc englobant, extraits
  d'autres documents, **le budget EN CARACTÈRES**
  (`maxContextChars` — Pigma ignore les jetons d'un modèle,
  l'implémentation convertit si son moteur le veut ; zéro : le
  contexte ne voyage pas).
- **`AiResult`** — scellée à trois formes : le texte qui se LIT
  (du Markdown, rien ne se pose), le REMPLACEMENT d'une plage (la
  correction, la modification), l'INSERTION à une position (le
  commentaire de documentation, la complétion). La réponse est une
  donnée, jamais une instruction.

Tout est immuable : le nul se vide partout, les listes se figent,
les bornes se vérifient (la plage inversée se refuse, le budget
négatif se refuse, la tâche nulle se refuse).

## La preuve

- `AiContractTest` (JVM pur) : la normalisation (nuls vidés,
  listes figées), la validation (bornes, budget, tâche), l'égalité
  des enregistrements par valeur.
- `PurityTest` : aucune classe de `jo.pigma.ai..` ne dépend
  d'`android..`.
- `./gradlew check` **vert** (les SEPT modules, politique comprise
  — 255 fichiers contrôlés), le vieux harnais 51/51.
- Le greppé du dépôt : AUCUN nom de fournisseur ni de modèle
  nulle part (la politique des références interdites y veillera
  quand l'hôte en posera la liste).

## Les limites honnêtes

- Le module ne contient RIEN d'autre : la préparation du contexte
  (B1) et les fonctions (B2) vivront aux chantiers suivants —
  l'interface est prête à les porter.
