# Démonstration du chantier 11 — l'appariement visuel

## Pourquoi ce chantier

L2 a livré la profondeur (chantier 10) ; son premier consommateur
d'éditeur arrive : quand le curseur s'assoit contre une parenthèse,
une accolade ou un crochet, **la paire s'illumine** — les deux bouts
encadrés. C'est la fonctionnalité la plus demandée d'un éditeur de
code, et celle qui éprouve la structure en lecture réelle : chaque
déplacement de curseur interroge la chaîne d'appariement.

## Ce qui a été construit

- **`StructureDocument.pairAt(offset)`** (dans `:syntax`) : le signe
  adjacent au curseur (à gauche d'abord — la frappe referme à gauche)
  et son partenaire, dans la chaîne tolérante.
- **La marche avant suit les jetons depuis l'ouvrant, ligne à
  ligne**, la profondeur de début de chaque ligne venant de L2 (le
  point de contrôle : jamais de relecture depuis le début du
  document). Le partenaire vit au premier fermant qui referme la
  profondeur d'avant l'ouvrant.
- **La marche arrière porte sa file** (la règle de pile) : les
  fermants à sauter s'accumulent d'une ligne à l'autre, l'ouvrant
  qui vide la file est le partenaire.
- **La vue dessine** (`EditorView`) : deux cadres fins autour des
  bouts visibles de la paire ; le calcul se cache par (curseur,
  révision) — un déplacement ne paie la marche qu'une fois.
- **Le curseur par programme** : `caretTo(offset)` (un hôte peut
  placer le curseur ; la paire s'y recalcule) et `bracketPair()` (la
  dernière paire calculée au dessin — le harnais la lit).

## Les deux failles épinglées par les tests (et fermées)

1. **Le retour intra-ligne** : dans `weight0(int seed) {`, le `(` de
   `weight0(` referme à sa `)` AU MILIEU de la ligne, puis `{`
   relève la profondeur en fin de ligne. La première version sautait
   par la profondeur de FIN de ligne (la première ligne qui
   « finit » au niveau) et ratait le retour du milieu — elle
   désignait l'accolade de la méthode. La marche suit maintenant les
   jetons ligne à ligne ; L2 donne le point de contrôle de début de
   ligne, pas un saut à l'aveugle.
2. **La file perdue** : la marche arrière réinitialisait sa file de
   fermants à chaque ligne depuis la profondeur de L2 — la file se
   porte d'une ligne à l'autre (la règle de pile) ; un point de
   contrôle par ligne la perdait, l'accolade de classe désignait
   l'accolade d'une méthode. La file se porte, point.

Une borne honnête : la marche renonce au-delà de 4 000 lignes (la
paire se déclare trop loin) — le corpus de 1 780 lignes n'y touche
pas, la mesure dira si un plus gros document l'exige.

## Ce qu'on voit (comment rejouer)

    ./gradlew check
    adb install sample/build/outputs/apk/debug/sample-debug.apk

Sur l'appareil : ouvrir le gros fichier, toucher près d'une accolade
— la paire s'encadre aux deux bouts (même hors fenêtre pour le bout
visible). Le harnais vérifie la marche depuis le tampon seul : étape
8, « accolade ligne 6 ↔ ligne 16 (marche de 10 lignes) », et la
marche inverse désigne l'ouvrante.

## Résultats constatés

| Mesure | Valeur |
| --- | --- |
| Tests au dépôt | **99 verts** dont 3 dédiés (corpus : 200 signes interrogés, complémentaire + symétrie ; près et loin ; orphelins sans partenaire) |
| Harnais JVM | étapes 8-9 : appariement vérifié + symétrie, structure au panneau (profondeur 1 dans le corps, 33/1 780 lignes analysées — la paresse tient) |
| APK de démonstration | 89,0 Ko |

## Limites assumées (et suite)

- L'appariement par type n'est pas vérifié (tout fermant referme
  tout ouvrant dans la chaîne tolérante) — sur un code bien formé
  les deux règles coïncident, le corpus le prouve (200 signes,
  zéro écart).
- Les guides d'indentation suivent au chantier 12, la construction
  release de mesure au chantier 13.
