# Démonstration du chantier 1 — `:core` et éditeur minimal

## Ce qui a été construit

- Module **`:core`** (JVM pur, package `jo.pigma.core`, garanties de
  pureté par test ArchUnit) :
  - `TextBuffer` : tampon à trou, offsets UTF-16, index de lignes
    incrémental (séparateur `'\n'` seul), révision monotone, écouteurs de
    changement ;
  - `TextChange` (édition décrite, immuable) et `TextPosition`
    (ligne/colonne, immuable) ;
  - `TextTransaction` : groupe d'éditions appliquées immédiatement,
    engageable en une unité d'annulation, retour arrière exact (décision
    004 : `close()` engage, le retour arrière est explicite) ;
  - `UndoStack` : pile bornée (256 unités par défaut), branche de
    rétablissement effacée par une édition fraîche, `undo()`/`redo()`
    renvoient les changements appliqués au tampon ;
  - `jo.pigma.core.internal.UndoUnit` : unité d'annulation interne
    (package `internal`, hors API contractuelle).
- Conventions racine étendues : modules JVM purs compilés avec le
  drapeau `--release 17`, JUnit commun à tous les modules, ArchUnit dans
  le catalogue de versions.
- **Éditeur minimal dans `:sample`** : `EditorView` dessine le tampon
  (police à chasse fixe), reçoit l'IME (frappe, retour arrière, zone de
  composition soulignée), place le curseur au toucher ; `MainActivity`
  expose les boutons Annuler/Rétablir et une ligne d'état (révision,
  ligne/colonne, longueur). Chaque retour de l'IME est une transaction,
  donc une unité d'annulation.
- Correctif du contrôle de politique : la recherche de « type public sans
  Javadoc » balaie maintenant le texte où seules les chaînes sont
  neutralisées — une classe citée dans une chaîne de caractères (le texte
  de départ de l'éditeur) ne déclenche plus de faux positif.

## Ce qu'on voit dans le sample

L'application ouvre un écran unique : le texte de départ (un petit
source Java) déjà éditable. En haut du clavier virtuel, la zone de
composition souligne le mot en cours. En bas : deux boutons **Annuler**
et **Rétablir**, grisés selon l'état de la pile, et une ligne d'état du
type « rév. 14 · ligne 3, col. 7 · 128 car. » — chaque frappe validée
fait avancer la révision, chaque annulation la fait avancer aussi (les
inverses sont des changements à part entière).

## Comment vérifier à la main

1. Compiler : `./gradlew :sample:assembleDebug` ; l'APK est dans
   `sample/build/outputs/apk/debug/sample-debug.apk` (23 Ko).
2. Installer : `adb install sample/build/outputs/apk/debug/sample-debug.apk`.
3. Toucher le texte : le clavier s'ouvre, le curseur se place à
   l'endroit touché.
4. Taper un mot : il apparaît souligné pendant la composition, puis se
   fixe au commit ; la révision avance d'une unité par frappe validée.
5. Appuyer sur **Annuler** plusieurs fois : le texte revient pas à pas
   jusqu'au texte de départ ; **Rétablir** rejoue les mêmes éditions.
6. Effacer avec le retour arrière, insérer des sauts de ligne : la
   révision et la position suivent.

## Résultats constatés (machine de build du chantier)

| Commande | Résultat | Détail |
| --- | --- | --- |
| `./gradlew check` | **vert** | Checkstyle sur `:core` et `:sample`, lint, tests, politique (14 fichiers Java), références interdites (42 fichiers) |
| `./gradlew test` | **vert** | 31 tests, 0 échec : 13 tampon, 9 transactions, 7 pile, 1 différentiel aléatoire (4 graines × 600 opérations), 1 pureté ArchUnit |
| `./gradlew :sample:assembleDebug` | **vert** | `sample-debug.apk`, 23 423 octets (6 917 au squelette : le cœur et la vue pèsent ~16 Ko) |
| `scripts/check-code-policy --selftest` | **vert** | 12 violations détectées sur les fixtures, 4 catégories couvertes |

Le test différentiel mérite une note : après correction d'erreurs
d'arithmétique dans les tests eux-mêmes, il fait tourner 2 400
opérations aléatoires (insertions, suppressions, remplacements,
annulations, rétablissements, retours arrière de transaction, texte non
BMP, `\r`, `\n`) et compare après **chaque** opération le texte, la
structure de lignes, les conversions offset/ligne et les indicateurs
d'état à un modèle de référence indépendant écrit sur `StringBuilder`.
C'est l'embryon du futur test de propriété de cohérence incrémentale du
moteur de coloration.
