# Chantier 71 — le fil de fond ne se tait plus en échec (D9)

## La consigne

Le défaut D9 du rapport : le fil de remplissage attrape
`RuntimeException` sans journal ni compteur — un lexeur qui échoue
de façon déterministe relançait la même tentative à chaque kick
(chaque édition, chaque dessin) sans que personne ne le sache, et
`passBeginNanos` restait posé : la passe suivante mesurait une
durée fausse.

## Le correctif

`BackgroundFill` :

- `sliceFailures` (`AtomicLong`) : les échecs de tranche se
  comptent depuis l'ouverture ;
- `lastFailure` : le message du dernier échec se garde ;
- le `catch` : compte, garde le message, journalise sur
  `System.err` (une ligne par échec — le message s'y lit), referme
  la montre (`fillNanos` se paie, `passBeginNanos` repart à zéro —
  la passe suivante mesurera juste), puis s'arrête comme avant (le
  prochain kick repart sur un cliché propre) ;
- `sliceFailures()` et `lastFailure()` publics : l'hôte et le
  harnais y lisent l'état de santé du fond (zéro est la normale).

## La vérification

Tests du module `:syntax` verts, `./gradlew check` complet vert,
le vieux harnais vert (49/49 — ses scénarios ne déclenchent aucun
échec de tranche, `sliceFailures()` y resterait à zéro).
