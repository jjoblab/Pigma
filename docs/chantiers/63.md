# Chantier 63 — l'hôte sans effort, le pincement, les README de module

## La consigne

Quatre demandes du propriétaire : consulter l'éditeur de référence, son module
LSP, pour voir son approche et améliorer la nôtre ; organiser le
module editor / l'EditorView de cette façon que l'application hôte
n'ait pas grand-chose à faire ; ajouter le pincement du zoom ; un
README par module.

## Ce que la référence enseigne

Le module d'intégration de l'éditeur de référence (Maven) : le client LSP vit derrière une FAÇADE — `LspEditor`
attache le serveur à la vue, porte la synchronisation du document,
pose les fournisseurs (complétion, survol, signature, diagnostics à
la marque de l'éditeur), et l'hôte de la référence pose la vue,
branche, écrit. Les fonctions s'y coupent une à une
(`isEnableHover` et ses sœurs), le temps d'attente des requêtes se
pose, les diagnostics se lisent par un conteneur. La leçon : le
CÂBLAGE est de la bibliothèque, pas de l'hôte — l'écran du sample
portait quatre cents lignes de câblage LSP qui n'avaient rien à
faire chez l'hôte.

## Le portage

- **`LspEditor`** (`editor/.../lsp/`) — la façade : `attach(view)`
  prend la vue, `connectInProcess` / `connectProcess` / `connect`
  branchent, `disconnect` coupe — entre les deux, TOUT ce que
  l'écran câblait vit dans la bibliothèque : l'initialisation, le
  `didOpen` du texte courant, le `didChange` amorti aux 300 ms
  (l'écouteur du tampon, le report reprogrammé à chaque édition),
  le survol (la réponse du serveur prime sur l'index local, 200 ms
  d'attente réglable, l'asynchrone remplace la réponse lente), la
  complétion (le cache par préfixe, la réponse asynchrone évince
  l'ancienne), l'aide aux paramètres (le cache par curseur, la
  génération déclasse la réponse d'avant), les diagnostics (la
  sévérité du protocole à la carte, le marqueur de la gouttière en
  vit). Les réglages de la référence suivent : les fonctions se
  coupent une à une (`setHoverEnabled`, `setCompletionEnabled`,
  `setSignatureHelpEnabled`, `setDiagnosticsEnabled`), l'attente se
  pose (`setRequestTimeoutMs`), l'hôte lit les diagnostics pour son
  panneau (`setDiagnosticsListener` — l'avis arrive sur le fil de
  l'interface).
- **`:editor` expose `:lsp` en api** : l'hôte ne déclare QUE la
  bibliothèque d'édition — le client LSP reste un module à part
  dans les sources, l'hôte qui ne branche jamais la façade ne le
  paie pas d'attention. Le sample retire sa dépendance directe.
- **L'écran du sample dégraissé** : 919 → 704 lignes. Le clic « LSP
  » ne porte plus qu'UNE ligne de branchement
  (`lsp.connectInProcess(new DemoLanguageServer(DOC_URI), DOC_URI,
  "java")`) ; le clic « LSP Lua » garde son espace de travail (le
  dossier du démo Lua dans le cache, l'exécutable EmmyLua) mais
  branche pareillement (`lsp.connectProcess(server, uri, "lua")`).
  Le détachement, les fournisseurs, les caches, l'écouteur du
  panneau : disparus de l'écran.
- **Le pincement** (`EditorView`) : deux doigts s'écartent — l'écart
  porte le facteur (le corps du départ l'attend), la ligne sous le
  foyer du départ demeure sous le foyer courant (le texte ne fuit
  pas sous les doigts). Les métriques se font vivantes (la chasse du
  monospace, la hauteur de ligne, le filet du curseur se
  recalculent), les plans de rendu se rangent (les abscisses y sont
  cuites à la chasse d'avant), le défilement se borne. Un geste en
  cours se range à l'engagement (la poignée se lâche, la sélection
  reste posée) ; l'appui final ne vaut pas un TAP (le curseur ne
  saute pas au dernier doigt levé) ; le doigt qui demeure après le
  pincement glisse sans sauter. Les bornes et le corps se posent par
  l'hôte : `getTextSizeSp`, `setTextSizeSp` (la ligne au milieu de
  l'écran y demeure), `setZoomBoundsSp` (8–40 sp par défaut), le
  pincement s'y serre toujours.
- **`MotionEvent` multi-doigts au harnais** : les événements du
  stub portent leurs doigts (POINTER_DOWN, POINTER_UP, l'indice du
  doigt dans les bits hauts, `getX(int)`, `getY(int)`) — l'appui
  d'un seul doigt garde sa voie courte, les scénarios existants ne
  changent pas.
- **La pompe du harnais** : `awaitText` draine les différés à
  l'attente — la façade marshalle les avis du serveur par `post`
  (la file différée du stub), l'attente doit pomper comme un fil
  d'interface vivant, sinon l'avis du serveur dort dans la file
  pendant que le scénario sonde le panneau.
- **Un README par module** : `core/` (le modèle de texte), `syntax/`
  (le moteur de coloration), `analysis/` (l'annotateur), `editor/`
  (la vue, les popups, la façade, le pincement — l'intégration
  minimale en tête), `lsp/` (le client, les trois raccordements), `sample/`
  (la démonstration, la preuve d'intégration). Le README racine
  porte la table des modules. Chacun : le rôle, les classes
  publiques, les règles du module, l'usage depuis l'éditeur, les
  tests.

## L'éprouve

Harnais **36/36** (deux scénarios neufs). « Façade LspEditor :
l'hôte ne câble plus rien » : la façade vit attachée et débranchée ;
le branchement porte l'avis du serveur à la carte (la ligne zéro le
porte) ; les fonctions coupées se taisent une à une (les diagnostics
taisent la ligne zéro, la complétion vide la carte, le survol retombe
sur l'index local, la signature range la carte) et reviennent (le
cache y répond) ; le débranchement rend le bouton. « Pincement : le
zoom au deux doigts » : le corps initial se lit en sp, l'écart
agrandit le corps (la chasse suit), le curseur n'a pas sauté au
doigt levé, le rapprochement rend le corps, les bornes de l'hôte se
posent et calent (le corps hors bornes se cale haut et bas,
l'API de l'hôte pose son corps, le pincement serre à la borne
basse), le tap suivant replace le curseur, le corps initial
revient. Les scénarios précédents se re-rangent (la pompe du
`awaitText` y tient l'avis du serveur vivant). Syntaxe **26/26**,
LSP **10/10**, politique **OK** (126 fichiers). L'APK rebâti
(6,9 Mo, signé debug) livré dans `download/`.
