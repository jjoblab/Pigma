# Chantier 66 — l'Entrée clôt la composition (B6)

## La consigne

Le défaut B6 du rapport : « l'Entrée insère un saut de ligne sans
clôturer la composition en cours » — le clavier logiciel qui
compose (accents, prédiction) laisse alors un état fantôme : l'IME
croit sa composition vivante derrière le saut de ligne inséré.

## Le correctif

`EditorInputConnection` — les DEUX voies de l'Entrée clôtent la
composition AVANT d'insérer :

- `sendKeyEvent(KEYCODE_ENTER / NUMPAD_ENTER)` appelle
  `editor.clearComposing()` puis insère le saut de ligne ;
- `performEditorAction` (la touche action du clavier) fait de
  même.

La complétion ouverte gardait déjà son comportement correct (la
carte prend la validation Entrée par `onEnter()`, le texte tapé
poursuit vers le tampon) — le rapport confirme que la vague 47 y
avait réglé la survie ; ce chantier ne touche que la composition.

## La preuve

Le scénario « IME : frappe, annulation, rétablissement » du
harnais réel (Robolectric) s'étend :

1. une composition se pose (`setComposingText("é", 1)`) ;
2. l'Entrée du clavier par événements arrive ;
3. vérifications : la composition s'est clôturée, UN seul saut de
   ligne s'insère, aucun texte fantôme ne reste derrière ;
4. les annulations rendent le texte original exact.

Le harnais à stubs (49/49) et le `./gradlew check` complet
restent verts.
