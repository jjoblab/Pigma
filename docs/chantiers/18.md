# Démonstration du chantier 18 — `:editor`, la bibliothèque

## Pourquoi ce chantier

La promesse centrale de l'architecture : **peu de modules, découpés
par fonctionnalité, pour qu'une application hôte n'ajoute qu'une ou
deux dépendances**. La vue d'édition vivait encore dans le sample —
l'application de démonstration — aucun hôte n'aurait pu la prendre
sans emporter le labo entier.

## Ce qui a été construit

- **Le module `:editor`** (bibliothèque Android,
  `com.android.library`) : `EditorView` et `RenderCache` y
  déménagent (package `jo.pigma.editor`), avec `EditorThemes` — les
  deux palettes deviennent celles de la bibliothèque (un hôte peut
  apporter les siennes : le thème se passe en argument).
- **Les dépendances s'inversent** : `:editor` expose en `api` le
  cœur, le moteur et l'annotateur ; **`:sample` ne déclare plus que
  `:editor`** — le cas courant de l'architecture tient littéralement :
  une ligne dans le build de l'hôte, rien d'autre.
- **La vue de bibliothèque démarre vide** : l'hôte charge son contenu
  (`setLanguage`), et `UndoStack.clear()` (nouveau dans `:core`)
  permet de ne pas faire du chargement une édition à défaire — le
  sample s'en sert au démarrage.
- **Le test suit sa classe** : `RenderCacheTest` déménage dans
  `:editor` (le test d'unité d'une bibliothèque Android).

## Ce qu'on voit (comment rejouer)

    ./gradlew check          (109 tests, la bibliothèque incluse)
    bash scripts/open-harness/run.sh

Dans le dépôt : `editor/src/main/java/jo/pigma/editor/` — la vue, le
rendu, les thèmes ; `sample/` ne garde que l'instrument (l'activité,
les textes de démonstration, les boutons).

## Résultats constatés

| Mesure | Valeur |
| --- | --- |
| Modules du dépôt | **cinq** (:core, :syntax, :analysis, :editor, :sample) — l'architecture en prévoit six au maximum |
| Tests au dépôt | **109 verts** |
| APK de démonstration | 104,6 Ko (debug) · 73,6 Ko (release) |

## Limites assumées (et suite)

- Le découpage interne de l'architecture (packages `render/`,
  `input/`, `gutter/`…) reste à plat dans `EditorView` — il se fera
  quand les fichiers grossiront, pas avant (le plafond de 25 fichiers
  par package n'est pas en vue).
- La sélection (curseur, multi-curseurs) et l'accessibilité restent à
  faire dans `:editor`.
- `:lsp` n'est PAS créé : la règle du dépôt — aucun module avant la
  fonctionnalité qui le justifie — s'applique aussi aux modules
  prévus (le client branchera le jour où un serveur répondra).
