# Chantier 68 — le placeholder du pli se tape (B5)

## La consigne

Le défaut B5 du rapport : « le chevron du pli se dessine au mauvais
calque / le placeholder n'est pas tapable ». L'examen du code au
commit courant : les chevrons vivaient déjà au panneau de la
gouttière (la vague 49 les y avait posés — colonne des plis dans le
panneau, jamais sur le filet), le placeholder `{…}` se dessinait
mais AUCUN tap ne le servait : le doigt sur l'en-tête replié
essayait de poser le curseur dans la région cachée.

## Le correctif

- **`foldPlaceholderLeft(line)`** : la borne gauche du placeholder
  (après la fin visible de l'en-tête, le défilement horizontal y
  retranché).
- La voie du tap du texte : sur une ligne d'en-tête repliée, un tap
  AU-DELÀ de cette borne ROUVRE le bloc (`toggleFoldAt`) au lieu de
  poser le curseur dans la région cachée — la leçon de la référence
  : son « ... » s'y clique.

Le pli se referme toujours par la gouttière (chevron), les
diagnostics gardent la priorité au tap (le souligné rouge s'ouvre
avant).

## La preuve

Le scénario « plis » du harnais réel s'étend : le pli se replie par
la gouttière, le tap sur le placeholder rouvre (deux fois — le
scénario repart propre). 12 scénarios réels verts, 49/49 au vieux
harnais, `./gradlew check` complet vert.
