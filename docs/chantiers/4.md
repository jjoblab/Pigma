# Démonstration du chantier 4 — fenêtre paresseuse, points de contrôle, plafonds (E3)

## Ce qui a été construit

- **`:syntax` — la fenêtre paresseuse** : ouvrir ne lexe rien ;
  `lineTokens(n)` étend le préfixe contigu calculé jusqu'à la ligne
  demandée et jamais au-delà. La vue qui ne dessine que les lignes
  visibles ne paie que ce qu'elle montre.
- **Points de contrôle d'état, une ligne sur 256** : posés en lexant
  (toute passe), révisionnés par la règle d'arrêt (la queue épargnée
  reste prouvée, tous les points de contrôle passent à la révision
  courante quand la chaîne d'états se rejoint) ; une édition qui
  propage un état jusqu'à une zone jamais lexée y pose un point de
  contrôle plutôt que de lexe le reste. `releaseEntries(from)` laisse
  la vue libérer les entrées lointaines : les points de contrôle
  restent, un retour lointain repart du plus proche.
- **`advanceLexing(maxLignes)`** : remplissage par tranches bornées —
  le budget de temps du fil d'interface. Le moteur vit sur le fil qui
  édite le tampon : un vrai fil de fond annulable (résultats appliqués
  seulement si la révision du tampon correspond) viendra avec la vue
  complète.
- **Plafonds** : ligne de plus de 20 000 colonnes non colorée (jeton
  aucun, état reporté, les voisines intactes) ; dessin limité à
  10 000 colonnes (vue) ; `inBigFileMode()` au-delà de 2,5 M caractères
  ou 50 000 lignes — la coloration lexicale n'y est jamais coupée, L2
  et L3 à venir s'y couperont.
- **Sample** : le rendu ne dessine que les **lignes visibles** ; le
  doigt fait **défiler** verticalement (le toucher court place le
  curseur, le déplacement défile) ; la frappe amène le curseur dans la
  fenêtre ; le bouton **« Gros »** ouvre un document généré d'environ
  2 000 lignes avec une ligne monstre (25 000 colonnes : non colorée,
  dessin coupé) ; une **pompe** lexte le reste du document par tranches
  de 256 lignes entre les trames ; le panneau de diagnostic affiche
  « lignes lexées / total » qui monte pendant le remplissage.

## Ce qu'on voit (comment rejouer)

    ./gradlew :sample:assembleDebug
    adb install sample/build/outputs/apk/debug/sample-debug.apk

Appuyer sur **« Gros »** : la couleur apparaît aussitôt sur les lignes
visibles (la première coloration du panneau reste sous quelques
millisecondes — elle ne paie que la fenêtre, pas les 2 000 lignes),
tandis que « lignes lexées / total » monte vers le total en une
seconde environ (la pompe, par tranches entre les trames). Faire
défiler du doigt : les lignes se colorent à l'arrivée. La ligne
monstre s'affiche en texte brut, coupée au bord. Taper : « dernière
frappe » reste une ligne relue ; supprimer un `*/` : la propagation
relit jusqu'à la fermeture suivante ; le curseur suit la frappe en bas
de fenêtre. Les textes courts (Java, XML, JSON, SQL) et la bascule de
thème (sans retokenisation) du chantier 3 restent en place.

Côté tests : `./gradlew :syntax:test` — **31 tests verts**, dont la
paresse et ses bornes, les tranches, le saut lointain après libération
(245 lignes lexées pour servir la ligne 500, jetons égaux à un
document neuf), l'édition au-delà du préfixe (justesse vérifiée contre
un document neuf), les plafonds (monstre, frontière exacte de 20 000,
seuils gros fichier, L1 jamais coupée) et la non-régression des
sorties figées et du redémarrage.

## Résultats constatés

| Mesure | Résultat |
| --- | --- |
| Tests `:syntax` | **31 verts** (paresse, points de contrôle, plafonds, non-régression) |
| Première couleur, 40 lignes visibles (JVM) | **1,91 ms** (tout le document : 11,8 ms au chantier 3) |
| Remplissage complet, 2 010 lignes (JVM, tranches) | 10,7 ms |
| Frappe ordinaire / propagée (JVM) | 0,05 ms (1 ligne) / 0,03 ms (7 lignes) |

## Limites assumées (et suite)

- Le remplissage tourne **sur le fil d'interface, entre les trames**
  (tranches de 256 lignes ≈ une milliseconde) : le fil de fond
  annulable, avec application conditionnée à la révision du tampon,
  arrive avec la vue complète (`:editor`) — le moteur vit sur le fil
  qui édite le tampon.
- Le cache de rendu par révision de ligne et le partage des lignes
  identiques (spécifiés par la conception) relèvent de la vue complète.
- Ligne monstre : l'état du lexeur se reporte tel quel (approximation
  documentée — la ligne est une pathologie, la couche L1 ne s'y arrête
  pas).
- Kotlin (gabarits de chaîne, pile à internée) reste le prochain
  langage de la voie générée.

Prochain chantier recommandé : **Kotlin par la voie générée**
(descriptions, gabarits de chaîne multi-lignes par état, pile à
internée pour le test de redémarrage), puis la fusion des niveaux L2
(l'analyseur tolérant) une fois les relevés appareil faits.
