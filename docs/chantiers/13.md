# Démonstration du chantier 13 — la construction release de mesure

## Pourquoi ce chantier

Les relevés 4 et 5 ont isolé une part de coût que le code ne peut
pas corriger : **l'interprétation à froid** du premier lexage. À
l'ouverture du gros fichier, le moteur paie 5,93 ms au premier
passage puis 3,24 au second (tiède) ; la démo Kotlin, première
ouverte de la session, paie 2,15 ms pour 28 lignes. C'est le prix de
la construction debug (ART interprète avant de compiler) — la
mesure de référence doit venir d'une construction release, celle que
la documentation promet depuis le premier relevé.

## Ce qui a été construit

- **Le type de construction `release` dans `:sample`** : signé avec
  la clé debug (installable par `adb install` pour les relevés — une
  release non signée refuserait de s'installer) et **sans
  minification** : la seule variable qui change face au debug est le
  mode de compilation. La mesure y répondra sans confusion R8.
- Les deux APK de mesure dans `download/` :
  `pigma-sample-debug.apk` (89,0 Ko) et `pigma-sample-release.apk`
  (64,0 Ko).

## Ce qu'on voit (comment rejouer)

    adb install pigma-sample-release.apk

Sur l'appareil : le même parcours de relevé — ouvrir le gros
fichier (première coloration, trame d'ouverture : **le moteur y
devrait retomber vers ~1–2 ms** — c'est LA mesure qui tranche
l'interprétation à froid), basculer les thèmes (le régime établi),
taper un caractère (la frappe), copier les mesures. Le journal se
colle dans `docs/perf.md` comme aux cinq relevés précédents — la
ligne « appareil » dit toujours modèle et version d'Android.

## Résultats constatés

| Mesure | Valeur |
| --- | --- |
| Tests au dépôt | **99 verts** (aucun code ne bouge : la configuration seule) |
| APK release | **64,0 Ko**, installable, sans minification |
| APK debug | 89,0 Ko (livré avec, pour la comparaison à froid) |

## Limites assumées (et suite)

- La release de mesure est signée debug : elle n'est PAS une release
  de distribution (pas de clé de production, pas de minification) —
  c'est un instrument, pas un livrable.
- Sans appareil dans le bac à sable, la mesure elle-même attend le
  relevé 6 : mêmes colonnes, construction différente — la
  comparaison debug/release dira le poids exact de l'interprétation
  (les relevés 4 et 5 l'estiment à ~3 ms sur la trame d'ouverture).
- Suite : les consommateurs suivants de L2 (surlignage de portée,
  régions pliables) puis L3.
