# Chantier 70 — la version de document LSP par URI (D3)

## La consigne

Le défaut D3 du rapport : « les numéros de version de document sont
incohérents » — un `AtomicInteger` unique servait TOUS les
documents : deux documents alternés sur une même liaison voyaient
la version de l'un redescendre quand l'autre en montait ; le
protocole exige la stricte croissance PAR identifiant de document,
les serveurs y rejettent la notification.

## Le correctif

`LspSession` :

- `documentVersions` : `ConcurrentHashMap<String, AtomicInteger>`,
  un compteur par URI ouverte ;
- `didOpen` repart à 1 (le compteur neuf du document) ;
- `didClose` range son compteur (une réouverture repart de 1) ;
- `didChange` incrémente LE compteur du document changé
  (`computeIfAbsent` — un changement sans ouverture reste légal,
  le repli du protocole) ;
- l'ombre de synchronisation (`documentShadows`) suit exactement
  le même cycle, les deux cartes vivent ensemble.

## La preuve

Le test `didChangeVersionsGrowPerDocument` : deux documents ouverts
sur une même liaison, trois changements alternés — le document b
REPART à 1 (son compteur à lui, pas celui de a), le document a
monte à 2 sans jamais redescendre. 21 tests au module `:lsp`,
check complet vert (la machine du bac exige `--max-workers=1` —
4 Go de mémoire, le démon et le harnais s'entre-tuent sinon).
